## Why this matters

Each active terminal currently owns a 250ms interval. Every tick rereads validated metadata and the exit marker synchronously, and `runtime` entries survive after their timers clear. Runtime CPU/heap therefore grow with active/touched terminals. The full lightweight ID/owner index introduced by Plan 093 must remain intact so old records stay directly queryable without a new full scan.

## Steps

### Step 0: Prove Plan 093's projection contract exists

After the dependency row is `DONE`, require the exact downstream API Plan 093 owns. Do not substitute `loadAll()`/`listOwned()` fallbacks.

**Verify**: `rg -n "refreshIndex\(|getIndexed\(|listOwnedIndexed\(" src/background-tasks/task-store.ts` → all three public methods are present; `pnpm vitest run src/background-tasks/task-store.test.ts -t "serves an old indexed ID with one metadata read and zero full scans"` → one pass. If either check fails, STOP for Plan 093 reconciliation.

### Step 1: Characterize work and memory shape

Add deterministic counters for metadata reads, exit-marker reads, scheduler callbacks, and retained map sizes. Test 0, 1, and 100 active tasks plus 10,000 settled records. Avoid wall-clock gates; use fake timers and operation counts.

Pin recovery/stop races: natural exit, missing exit marker, PID reuse, stopping process, external revision, and detach.

Create `task-manager.perf.test.ts` with tests named `characterizes supervision work:` for 0/1/100 active and 10,000 settled fixtures.

**Verify**: `pnpm vitest run src/background-tasks/task-manager.perf.test.ts -t "characterizes supervision work:"` → expected red before implementation on one-interval-per-active and unbounded-heavy-map assertions, with deterministic counters rather than elapsed time.

### Step 2: Replace per-task intervals with one supervised scheduler

Use one manager scheduler (or a bounded timing wheel) for active tasks. Filesystem notification may wake it early, but periodic scanning remains a correctness fallback because notification delivery can be lost. Cache immutable task paths/identity in active runtime state so a normal tick does not reread full metadata.

A durable metadata refresh is required when external revision/takeover evidence appears. Keep process-tree verification cadence and safe stop semantics unchanged.

**Verify**: `pnpm vitest run src/background-tasks/terminal-supervisor.test.ts src/background-tasks/task-manager.perf.test.ts -t "one supervision scheduler|unchanged active tick"` → one manager scheduler for 100 active tasks, zero full metadata reads on unchanged ticks, periodic fallback after a dropped notification, and unchanged process-tree verification cadence.

### Step 3: Bound the in-memory settled mirror

Retain all non-settled tasks plus at most the existing settled replay count per owner in the heavyweight manager snapshot map. Serve older ID lookups/list history through Plan 093's derived in-memory metadata-path index with direct record reads. Eviction removes only manager snapshot/runtime objects; never the store's ID/owner path entries and never files.

Ensure a pending/claimed completion cannot be evicted before delivery, even if settled. Define this as a positive invariant in code/tests.

**Verify**: `pnpm vitest run src/background-tasks/task-manager.perf.test.ts -t "bounds heavyweight settled state|queries an evicted old ID directly"` → 10,000 settled records retain only configured heavy replay/pending-claim state; old `get(id, owner)` performs one direct metadata read and zero `loadAll()` calls while the complete Plan-093 path index remains intact.

### Step 4: Validate recovery and teardown

Run restart/takeover tests with active/stopping tasks and retained claims. `detach()` must cancel the one scheduler and all watchers with no callbacks afterward.

**Verify**: `pnpm vitest run src/background-tasks/task-manager.test.ts src/background-tasks/terminal-supervisor.test.ts -t "restart|takeover|detach|stopping" && pnpm vitest run test/integration/terminal-completion-recovery.test.ts --fileParallelism=false` → exit 0; detach leaves zero scheduled callbacks/watchers.

### Step 5: Run full gates and record non-gating measurements

Record event-loop delay/RSS for 0/10/100 active and 10,000 settled fixtures before/after. Do not turn machine-dependent values into CI thresholds yet.

**Verify**: all command-table gates pass.
