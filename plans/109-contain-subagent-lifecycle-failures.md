## Why this matters

Several rare failures escape their intended boundary: an async-iterable backend rejection is unobserved; one delivery listener can abort all manager notifications and drained results can be lost if `sendMessage` throws; an unrelated malformed role blocks every explicit role; and a Herdr pane remains orphaned if command startup fails after pane creation. These are small, high-confidence lifecycle gaps that share tests and ownership boundaries.

## Current state

- `src/subagents/manager.ts:677` starts the async iterator with `void (async () => ...)()` and no rejection owner; `notify()` at `:851-853` calls listeners without isolation.
- `src/subagents/index.ts:206-220` drains deferred payloads before `pi.sendMessage`; `src/subagents/delivery.ts:40-44` clears `pending` in `drain()`, so a synchronous send throw loses the payload.
- `src/subagents/tools.ts:137` rejects a selected role whenever any `loadRoles().warnings` exists, even when another role is malformed.
- `src/terminal-host/herdr.ts:183-195` may move a pre-existing workspace anchor to a `shell` tab or create a new tab/pane, then returns command-run failure without child-target cleanup.

Existing conventions: close/cancel batches isolate per-ID errors; terminal delivery restores durable retry ownership instead of dropping failed sends; terminal-host methods return typed `{ ok }` results.

## Steps

### Step 1: Supervise async-iterable backend failure

Add a backend fixture that emits one event then rejects. Catch iterator failure, convert it into exactly one failed terminal outcome, and ensure the child/controller is removed and queue capacity releases. Late events after settlement remain ignored.

Name the regression `contains async iterator rejection`.

**Verify**: `pnpm vitest run src/subagents/manager.test.ts -t "contains async iterator rejection"` → one failed snapshot/settlement, released capacity, removed controller, ignored late event, and zero `unhandledRejection` observations.

### Step 2: Make notifications and delivery retry-safe

Isolate listener exceptions so remaining listeners still run. Do not silently swallow: route a bounded diagnostic callback if one exists. Change deferred delivery to claim/peek then acknowledge removal after successful `sendMessage`, or restore failed payloads at the front preserving order. A synchronous throw must leave results retryable and must not duplicate successful earlier payloads.

**Verify**: `pnpm vitest run src/subagents/manager.test.ts src/subagents/delivery.test.ts src/subagents/index.test.ts -t "isolates listener failure|retries deferred delivery"` → first/middle send throws preserve FIFO retry, successful earlier IDs do not duplicate, consumed/pruned IDs stay consumed, later listeners run, and bounded diagnostics receive one error.

### Step 3: Scope role warnings

Represent warnings with affected role ID or global-file scope. Reject only the selected role whose entry is invalid; valid built-ins/overlays remain usable when another entry has an unknown field/tool. File-level parse/size/read failure may still block use of overlays while built-ins remain clearly available according to existing fallback semantics.

**Verify**: `pnpm vitest run src/subagents/roles.test.ts src/subagents/tools.test.ts -t "scopes role warnings"` → malformed custom role does not block `research`, selected malformed role reports only its warning, and global parse/size/read failure follows built-in fallback semantics.

### Step 4: Close panes after failed command start

If Herdr pane creation/split succeeds and `pane run` fails, best-effort close exactly that newly created child pane before returning failure. Never close or attempt to reverse-move a pre-existing workspace anchor: on workspace placement the anchor has already been intentionally moved to a `shell` tab, and it remains as the preserved recovery/inspection shell after child-start failure. Include that fact in the returned error. If child-pane cleanup also fails, include bounded cleanup context while retaining the primary startup error.

For a newly-created tab whose root pane is itself the failed child target, `closePane(newChildId)` must close that last pane/tab. For split-from-existing-tab/workspace paths, close only the new split. A workspace anchor intentionally moved to a `shell` tab remains a user-visible recovery shell—not an orphan—and the returned failure must name its preserved tab/pane so the operator can reuse/close it. Never reverse-move or close that pre-existing anchor automatically.

**Verify**: `pnpm vitest run src/terminal-host/herdr.test.ts -t "cleans failed child start"` → new-tab root failure closes the new child/tab; split failure closes only the child split; workspace failure closes the child but preserves/names the relocated anchor shell; cleanup failure retains primary error plus bounded cleanup context.
