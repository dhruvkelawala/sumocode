## 4. Regressions from the rewrite

1. **Tighter arm's escape hatch is asserted, not true.** `spec.md:21,116` and `plan.mdx:314–321` promise the temp-file path survives narrowing; Pi creates that file only when Pi truncates (`bash.js:209–233`). Minimal fix: either state that the tighter handler persists the discarded content to its own run-owned temp file and appends the path, or drop the "can always fetch" promise and record the arm as "narrow and discard".
2. **Record fields live only in the plan.** `SessionMetrics`, `StruggleFacts`, `HarnessVariant`, `EvalRun`, `Fixture` are enumerated at `plan.mdx:181–260`; `spec.md:142` names the types and no fields. The spec is declared the contract (`spec.md:3`), so the fields will drift. Minimal fix: copy the field lists into `spec.md` § Records or state that the plan's DataModel is normative for shapes.
3. **Threshold comparator and assertion types dropped from the spec.** US 37 promises "a stated threshold and comparator"; only `plan.mdx:395` states "pass at or above". Assertion `type: shell | git | trace` and weights appear only in `plan.mdx:397–404`. Minimal fix: one sentence in `spec.md` § Records.
4. **`--reps` "clamped to the fixture's own minimum"** (`spec.md:103`) is ambiguous (max(reps, min_reps)? reject below?). Plan says 3–5 with no upper bound. Minimal fix: "`--reps` below `min_reps` is raised to `min_reps` with a stderr diagnostic; no upper clamp."
5. **Viewer URL and gist filename dropped.** First review asked for the viewer URL to move into the standalone contract; the rewrite removed it from both documents. Minimal fix: "viewer URL is Pi's `getShareViewerUrl(gistId)`; uploaded file is `session.html`."
6. **"Surface the existing gist" on ambiguous upload** (`spec.md:153`) has no mechanism. Minimal fix: "on exit 0 with no parseable URL, report the raw `gh` stdout/stderr and do not retry" — or specify the `gh gist list` lookup.
7. **Plan's Records section says "pinned to a revision"** (`spec.md:142`, `plan.mdx:123`) but no revision is named anywhere. Either name it or delete the sentence.
8. **Polling predicate framed as non-heuristic while being one** (`plan.mdx:278`). Minimal fix: reword to "a declared, versioned, reported argument pattern" and declare it.
9. **Plan/spec disagree on the corrections count** (`plan.mdx:22` two vs three). Trivial fix.
10. **State directory and its override** (`plan.mdx:434`) are absent from the spec; the spec only says "outside the repository" (US 62). Minimal fix: name the directory (e.g. under the existing SumoCode state dir) and the override variable.
11. **Diagram/table drift.** `HarnessVariant.axis: quality | experience` (`plan.mdx:223`) while the experience track is deferred and out of scope (`spec.md:175`); `Fixture.seed_repo: string` (`plan.mdx:249`) reads as a path, conflicting with "synthesized, never copied" and "never a path" for source. Architecture diagram and run-protocol diagram are otherwise consistent with the text.
12. **Reader reuse vs diagnostics.** `spec.md:107` mandates reusing the existing reader for "tree structure", but `readSessionEntries` swallows malformed lines with no diagnostic, contradicting US 19 and the malformed-line tests at `spec.md:159`. Minimal fix: reuse `listSessions`/`readSessionInfo` for discovery and headers only; the analysis module owns line parsing.
13. **Typo** `spec.md:63` "workspaceso".

## 5. Remaining blocking findings

1. **Slice 1 lacks its normative output contract.** `spec.md` must carry: JSON top-level shape with a version field; per-session and summary field names (lift from `plan.mdx:181–217`); numeric exit statuses including the partial-scan case; `--root` default resolution (explicit: `getAgentDir()/sessions`, recursive over `--<cwd>--/` subdirectories, or a single project directory) and `PI_CODING_AGENT_SESSION_DIR` precedence; `--since` semantics (session header timestamp, inclusive, UTC); `--model` matching rule; the polling name set and the `terminal_start` pattern; definitions of `repeat_pairs` (distinct keys with count > 1, or occurrences beyond the first; consecutive or anywhere; argument canonicalisation), `fail_repeat_pairs` (both fail, or any fail), `error_streak_max` scope, `compaction_pressure` denominator, `Location`; the branch rule (root→last-entry path) and the cross-file `parentSession` rule. Without these an agent invents ~a dozen decisions that determine every number.
2. **Tighter-arm data-loss semantics** (regression 1) must be decided before slice 2, and the variant transport (variable name, values, which entry installs the hook, ceiling, tool families) must be written down.
3. **Fixture manifest and launch argv** for slice 3 remain absent; the first review's "one complete fixture as the normative example" was not delivered. Not blocking slice 1.

## 6. Slice-1 implementability assessment

An agent with only `spec.md` could build *a* `trace --root <dir> --json` that passes tests it writes itself. It could not build the one intended, because it would have to invent:

- root default and recursion rule; `--since`/`--model` semantics and whether "group by" (US 15) implies a flag;
- the JSON object shape, version key, and every metric field name;
- exit code values and what an incomplete scan returns;
- the polling name set and the `terminal_start` command pattern, and the suppression-list shape in `--json`;
- repeat pair / fail-repeat / streak / compaction-pressure definitions and argument canonicalisation;
- which branch is "the identified branch" and how `parentSession` forks are treated across files;
- how compaction/branch-summary usage and non-assistant model calls are counted;
- the terminal table layout and stderr diagnostic format;
- where the launcher dispatch script lives and how `trace` coexists with the launcher's positional-path parsing (`bin/sumocode.sh:272` precedent for `doctor|diag|task` is adequate but unnamed in the spec);
- whether malformed-line diagnostics come from the reused reader (they cannot) or a new parser.

Slice 1 is correctly sequenced and independently shippable in structure; it is not yet independently *specified*.
