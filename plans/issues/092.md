# [P0 · M1] Make PTY test children credential-safe and state-hermetic

## Summary

Real-process integration tests should not inherit credential-shaped environment variables or a developer's normal Pi durable state. Make the shared PTY harness safe by default while preserving explicit synthetic per-test overrides.

## Public scope

- Scrub provider/credential-shaped parent environment keys before spawning test children.
- Give each child an isolated temporary Pi state root unless the test explicitly supplies one.
- Preserve benign process variables needed for executable resolution and terminal behavior.
- Clean only harness-owned temporary roots; never remove caller-owned paths.
- Keep production child-process environment behavior unchanged.

## Acceptance criteria

- Synthetic credential-shaped parent keys are absent in the child.
- An explicit synthetic test override remains available to the child.
- State roots are private, unique, and cleaned after child teardown.
- Caller-supplied roots are preserved.
- Integration tests boot offline without reading normal user state.
- Typecheck, build, lint, unit, and integration gates pass.

## Verification

```bash
pnpm exec tsc --noEmit && pnpm build
pnpm lint
pnpm test
pnpm test:integration
```

## Dependencies

None. Internal milestone: M1. Full security evidence and executor detail are intentionally retained outside this public issue.
