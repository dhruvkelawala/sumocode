# [P1 · M2] Bound child-process protocol buffers

## Summary

Child JSON-line and diagnostic streams need explicit memory bounds. Oversized or unterminated protocol frames should fail the producer deterministically instead of allowing unbounded host memory growth.

## Public scope

- Define documented maximum frame, unterminated-buffer, stderr-tail, and retained-result sizes.
- Enforce limits before buffers grow beyond their caps.
- Treat an oversized JSON protocol frame as fatal; never truncate JSON and continue parsing it.
- Keep bounded human-readable tails with a clear truncation marker.
- Settle pending requests/runs exactly once and clean timers/listeners.

## Implemented size policy

All limits are UTF-8 byte limits and live beside the shared decoder in `src/child-protocol.ts`:

- JSON frame: 8 MiB.
- Unterminated JSON buffer: 8 MiB. It matches the frame cap so any valid frame may arrive in small chunks.
- Retained stderr tail: 64 KiB, including `[earlier output truncated]` when older bytes are dropped.
- Retained child result payload: 4 MiB per run, including one `[output truncated]` marker when later bytes are dropped. Completed assistant, user, and tool-result text, image data, thinking text, serialized tool-call arguments/details, native tool events, and the current assistant stream share that aggregate budget. The stream's provisional bytes are reclaimed when its completed assistant message replaces it. Ordinary structured values retain their object shape; oversized values become a bounded serialized preview. Opaque replay-only signatures, diagnostics, and deferred-provider payloads are not retained in task results. Structural identifiers are UTF-8 capped at 256–512 bytes and name lists at 64 entries; entry cardinality remains Plan 107.

The frame decoder fails closed rather than clipping JSON. The larger frame cap preserves rich Pi event payloads; the smaller retained-result cap limits long-lived task state after decoding. Byte-aware head/tail trimming drops incomplete UTF-8 boundary bytes rather than emitting replacement characters.

Final assistant delivery has priority inside the same cap. If earlier completed text already forced truncation, the latest non-empty assistant completion replaces that retained transcript text and carries the run's sole marker. A later thinking-only or tool-call-only frame cannot erase an earlier deliverable answer; non-text payloads receive priority replacement only when no deliverable assistant text exists. Native task replacement clears prior message/error/tool-argument/tool-output text while preserving bounded structural metadata and usage. Marker presence is tracked separately from exhausted headroom, so later turns can use the remaining cap; further omissions reuse the durable marker instead of latching retention or adding another. If a truncated provisional stream masks an interleaved completed message, the completion inherits the marker before the provisional text is cleared. `finalText` aliases the latest assistant transcript text and is not charged a second time. Tradeoff: bounded final delivery may discard earlier human-readable transcript text; the marker makes that loss explicit. This policy bounds retained text bytes only; transcript-array/cardinality scaling remains Plan 107.

Protocol failure or cancellation starts TERM→KILL but retains task/fork/concurrency ownership until the live child reaches `close`. A process `error` emitted after termination starts cannot settle the run or dispose the force-kill timer; a true spawn error with no owned child still settles immediately.

## Acceptance criteria

- Boundary tests cover just below/at/above each limit and many small chunks without a delimiter.
- Multibyte input and final partial lines are handled correctly.
- Failure diagnostics are bounded and do not echo complete producer content.
- Cancellation/child-exit behavior remains correct.
- Full unit and integration gates pass.
- Final-review regressions prove marker relocation through manager/wait delivery, byte-safe 16 KiB/48 KiB projections including short aggregate tails, bounded and replaceable structured/native args without repeated-marker growth, non-text message payload accounting, text-less-turn final delivery, malformed-part containment, structural-metadata caps, interrupted-child `error`/`close` ownership, mid-stream aggregate accounting, and stream/final replacement. Pre-repair mutation runs fail each retained-payload-owner finding.
