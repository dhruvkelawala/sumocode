# [P1 · M2] Redact sensitive terminal data before session publication

## Summary

Terminal commands and output can contain credential-shaped material. Apply the existing Activity redaction policy before terminal projections enter persistent session messages or tool-result details, while preserving raw owner-only logs for debugging.

## Public scope

- Reuse one existing redaction policy across terminal start/check/wait/stop/list and completion publication.
- Redact before truncation so a partial line cannot separate a label from its value.
- Omit invocation material where the UI does not require it.
- Preserve stable delivery identity, status, exit data, and owner-only raw logs.
- Do not rewrite historical sessions or logs.

## Acceptance criteria

- Synthetic secret-shaped values do not appear in session-facing messages/details.
- Benign diagnostic output remains useful.
- Passive/wake completion and observation race semantics remain unchanged.
- No claim is made that heuristic redaction proves arbitrary data secret-free.
- Full unit and integration gates pass.

## Verification

```bash
pnpm exec tsc --noEmit && pnpm build
pnpm lint
pnpm test
pnpm test:integration
```

## Dependencies

None. Internal milestone: M2. Exact credential patterns and evidence locations are intentionally omitted from this public issue.
