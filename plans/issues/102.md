# [P1 · M2] Remediate reachable dependency advisories

## Summary

The development dependency graph contains high-severity advisories, including paths used by optional Pi runtime capabilities. Because Pi is consumer-provided through peer dependencies, user-facing remediation requires an upstream fixed Pi release and an honest minimum peer version; local overrides are development-only.

## Public scope

- Map each high advisory to dependency chain, runtime/dev role, fixed version, and verification owner.
- Prefer an aligned supported Pi patch release and raise the peer minimum when that release contains the fix.
- Use a narrow transitive override only for the local development graph when parent semver and focused compatibility tests permit it; never claim that consumers inherit it.
- Add a machine-checked audit policy that rejects unclassified, stale, expired, or unremediated high/critical findings while allowing explicit, expiring upstream-blocked records.
- Keep provider verification offline with mocked transports and synthetic inputs.

## Acceptance criteria

- Every high/critical advisory has a reachability classification enforced by a tested policy checker.
- Consumer-runtime findings are fixed by an enforced upstream Pi minimum or recorded as upstream-blocked with owner/expiry.
- Local graph remediation is clearly distinguished from consumer runtime status.
- Pi packages remain version-aligned and pass the compatibility matrix.
- No broad audit suppression is added.
- Full unit/integration/typecheck/build/lint gates pass.

## Verification

```bash
pnpm vitest run scripts/check-dependency-audit.test.mjs
node scripts/check-dependency-audit.mjs
pnpm exec tsc --noEmit && pnpm build
pnpm lint
pnpm test
pnpm test:integration
```

## Dependencies

No hard prerequisite is required for classification or upstream reporting. If a fixed Pi candidate exists, verify the minimum and candidate with the compatibility matrix when available, or the existing explicit-version smoke command otherwise. Internal milestone: M2. Exact dependency paths and exploit details are intentionally omitted from this public issue.
